# karaoke-cli 1.0.0

First release. Offline CLI for vocal/instrumental separation and lyric
transcription, built on `candle-roformer` 1.0.0.

## Highlights

- Directory and multi-file input with a stable non-recursive scan, per-file
  preflight, continue-on-error, per-input error causes and a nonzero exit when
  any input fails.
- `--custom_output_names '<json>'` for per-stem output basenames, including the
  vocal `.txt`/`.json` sidecars; unknown stems, absolute paths and `..` are
  rejected before anything is written.
- `--list_models`, `--list_filter`, `--list_limit`, `--list_format pretty|json`
  over a shipped metadata catalogue. Metadata only: the CLI never downloads or
  redistributes weights.
- Diagnostics: `--log_level`/`--debug` with timestamps and module targets,
  per-stage timings, errors carrying the input path and cause, and `--env_info`
  (CLI and dependency versions from the lockfile, compiled CUDA/Metal features,
  device probe, parallelism, resolved model paths).
- Named multi-stem output through the library API while keeping the two-stem
  convenience, correct residual semantics, and `--single_stem <name>` in the CLI.
- Output formats WAV (IEEE f32, unchanged default), FLAC and MP3, with
  `--output_bitrate`, `--sample_rate`, and a clear rejection for M4A/AAC.
- Level processing: peak normalization (default `0.9`), amplification
  (default `0.0`, off), `--invert_spect`, and a documented residual invariant
  (`vocals + instrumental = input`, within f32 tolerance, in exact-residual mode).

## Assets

| Platform | File |
|---|---|
| Windows x86_64 | `karaoke-cli-v1.0.0-windows-x86_64.zip` |
| Linux x86_64 | `karaoke-cli-v1.0.0-linux-x86_64.tar.gz` |

Each asset ships with a `.sha256` file. Both binaries are CPU builds with the
C runtime linked statically; no toolchain or extra DLLs are required.

## Weights are not bundled

Model checkpoints and Whisper assets must be supplied locally. `--list_models`
prints where each catalogue entry's weights come from; nothing is fetched.

## Verification

- Full suite on Linux and Windows CI: 21 tests passed, including
  `a1ea0a4..v1.0.0` behaviour for every CLI flag above.
- `cargo fmt --all -- --check` clean.
- Release binaries are smoke-tested in CI (`--version`, `--list_models`,
  `--env_info`) before upload.
- Tests use generated audio and tiny synthetic weights; they say nothing about
  real model quality.

## Known limits

- CPU inference only in these binaries. CUDA and Metal builds exist as Cargo
  features but have not been tested on hardware here.
- Transcription uses Whisper on the vocal stem; it can hallucinate on singing
  and produces segment-level, not word-level, timestamps.
- M4A/AAC output is intentionally unsupported (no pure-Rust encoder).
