# karaoke-cli 1.0.1

Adds chunked separation with per-chunk progress, so a long CPU run is no longer
silent.

## What's new

- `--chunk_seconds <s>` separates the input in overlapping windows and prints
  one line per finished chunk:

  ```
    chunk 7/24 done (29%, 1837s elapsed)
  ```

  Progress goes to stderr; stdout keeps only the input line, the output paths
  and the batch summary.
- `--chunk_overlap <s>` sets the crossfade width. The default is 10% of the
  chunk clamped to 0.25–5 s; the overlap may not exceed half a chunk.
- Stitching is a linear crossfade: adjacent chunks' weights sum to exactly one
  at every sample, so a residual stem still satisfies
  `vocals + instrumental = input` (verified to f32 tolerance), and each chunk
  is computed with one overlap of extra context on both sides so the fade sits
  inside the model's receptive field.
- Level processing stays global: with `--chunk_seconds` the CLI applies
  `--amplification` and `--normalization` once to the whole file and normalises
  each stitched stem once, instead of letting the crate renormalise every chunk
  by its own peak.
- Chunking costs the overlap fraction of extra compute (about 11% at the
  default 10%) and does not change the output length.
- An input shorter than one chunk is still processed through the chunked path,
  so it keeps the same global level rules and reports `chunk 1/1`.

## Notes

- Without `--chunk_seconds` nothing changes: one separation call, no progress
  lines.
- `--transcribe` still runs once, on the stitched vocal stem.
- Chunk length must be at least 1 s; smaller windows would slice through the
  model's own analysis windows.

## Verification

- Full suite on Linux and Windows CI, including new tests for the residual
  invariant across chunk boundaries, the sum-to-one weight property at every
  frame, and whole-file level normalisation.
- Release binaries are smoke-tested in CI (`--version`, `--list_models`,
  `--env_info`) before upload.
