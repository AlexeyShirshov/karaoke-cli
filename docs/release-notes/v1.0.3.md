# karaoke-cli 1.0.3

Adds HyperACE v2 Inst support through candle-roformer 1.0.2 and rejects existing
output files before spending time on separation or transcription.

## Fixes and improvements

- Updated `candle-roformer` to 1.0.2, including BS-RoFormer HyperACE v2 Inst and
  instrumental-target model handling. HyperACE is also listed in the local
  metadata catalog; the CLI does not download model weights.
- Instrumental-target models save their direct estimate as `Instrumental` and
  the residual as `Vocals`. Transcription uses the vocal stem.
- Requested output paths are checked before audio decoding and inference,
  including TXT/JSON sidecars, custom names and single-stem selection. Existing
  outputs now fail immediately unless `--overwrite` is specified. The final
  pre-write check remains in place.

## Using HyperACE v2 Inst

Use converted fp32 safetensors weights and the adapted
`configs/bs_roformer_hyperace_v2_inst.yaml` profile from candle-roformer 1.0.2.
The author's unmodified YAML does not select the HyperACE head. Keep both:

```yaml
model:
  family: bs_roformer_hyperace_v2
training:
  target_instrument: instrument
```

These are required fields within the complete profile, not a complete config.
For instrumental-only output, use `--single_stem instrumental` without
`--transcribe`.

## Downloads and verification

- Windows CPU, Windows CUDA 12.8 and Linux CPU archives, each with SHA-256.
- The CUDA archive includes required CUDA runtime DLLs. Extract all files
  together and select `--device cuda`. Requirements are unchanged: NVIDIA Turing
  or newer (compute capability 7.5+), Windows driver supporting CUDA 12.8
  (570.65 or newer). Installing CUDA Toolkit is not required.
- All 31 local CPU tests pass, including early conflict rejection and
  instrumental-target stem labels with and without chunking. These use synthetic
  weights, not the real HyperACE checkpoint.
- Hosted release runners build/package CUDA but do not verify GPU inference.
